# /weekly 每周归集

项目根目录是包含 `PRD.md`、`知识点.md`、`inbox/` 的文件夹。所有命令都在根目录运行。识别规则、错因标签、批改符号、输出格式都在同目录的 [rules.md](rules.md)，**开始前先完整读一遍**。

## 用法

- `/weekly`：处理 inbox 里的全部文件（归集）。
- `/weekly 2026-W37`：处理并强制归到指定周。
- `/weekly sheet 2026-W37`：为该周出练习题并生成辅导单 PDF。

## 归集流程

1. **准备**：运行
   ```bash
   npm run ingest prepare
   ```
   输出末尾有一行 `MANIFEST [...]`，每个文件给出 `week`、`pages`（逐页图片路径）、`result`（要写的 pages.json 路径）。重复文件已自动删除并列出。没有文件就直接告诉家长。

2. **读知识点**：先读 `知识点.md`，拿到全部节点编号和标题。`knowledge_point` 只能填这里已有的编号，或者你新建的编号（新建时必须在 `new_node_title` 里写名字，否则页面上会显示成空标题）。

3. **逐页识别**：对每个文件，按顺序用 Read 工具查看每一张 `pages` 图片，按 rules.md 的「pages.json 格式」写出该页的对象。一页一个对象，顺序与 `pages` 一致，不得跳页、不得合并。看完一个文件的全部页后，用 Write 把数组写到该文件的 `result` 路径。
   - **没有人工确认环节，你的判断就是最终结果**。批改符号容易看反，订正常常是就地涂改，先看 rules.md 第 2 节的「批改符号」和「订正规则」再动手。
   - 拿不准的题，在 `analysis` 里写清楚存疑的地方，家长在错题本里会看到「批改存疑」标记。
   - 同一份 PDF 可能混有多个来源（学校课时练、学霸、计算能手……），逐页各自判断 `material_type` 和 `source_name`，程序会按来源拆分。
   - 页数多时可以分批读图，但最终 pages.json 必须是完整数组。

4. **落库**：运行
   ```bash
   npm run ingest apply
   ```
   （指定周时加参数，如 `npm run ingest apply 2026-W37`。）程序做判题、裁图、写 md、归档并清理工作目录，同时自动补上做题日期（取扫描件的上传时间）和下周预习清单。哪个文件缺 pages.json 会列出来，补上再跑一次即可。

5. **汇报**：告诉家长每份材料归到哪一周、来源是什么、新增几道错题、其中几道是「批改存疑」，以及识别出的下周预习知识点。可以提醒他在页面上：学习进度能按知识点/错因/单元/来源四个维度看并下钻到错题，错题本能按知识点筛选和排序。

## 出题与辅导单（`/weekly sheet <周>`）

1. 运行 `npm run sheet plan <周>`，得到本周重点问题（最多 3 个，含代表错题）和 `preview`（下周预习知识点）。
2. 按 rules.md 第 8 节为**每个重点问题**和**每个预习知识点**各出一组题，写成「practice.json 格式」，保存到 `/tmp/shuban-practice.json`。重点问题的组 `scope` 写 `错题`，预习的组写 `预习`。
3. 运行
   ```bash
   npm run sheet practice <周> /tmp/shuban-practice.json
   ```
   程序验算每题，算不通过的会丢弃并报数；丢弃多于 2 题时改题重来。PDF 在 `辅导单/<周>.pdf`，页面上的「下载辅导单」按钮同步可用。
4. 汇报重点问题、预习知识点和练习题数。

只改排版不重新出题时，用 `npm run sheet build <周>`。

## 注意

- 页眉上的班级、姓名、学号不写进任何输出。
- 算式一律写成人看得懂的样子：`96÷3+49`、`14×3=42`。**不要用 LaTeX，不要写 `$`、`\times`、`\div`**。
- 练习卷上只印题目，`hint` 只出现在答案页给家长看，所以 hint 可以直接写方法要点。
- 不要手工修改 `错题/` 下的 md，一切通过命令写入；`知识点.md` 只通过 pages.json 的 `nodes` 更新。
- 命令报错就原样转述，不要绕过。
