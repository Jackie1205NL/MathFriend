# 数伴识别与出题规则库

适用对象：苏教版小学数学三年级上册（2024 新版），家长辅导场景。程序侧的判题、进度、排版规则见 `PRD.md` 第 5 节；本文件只规定 Claude 看图时要产出什么。

**总原则：没有人工确认环节，你写进 pages.json 的结论就是最终入库的结论。** 宁可多花时间核对，也不要写不确定的判断；确实拿不准的，把疑点写进 `analysis`，家长在错题本里会看到「批改存疑」标记。

## 1. 材料类型（material_type）

| 类型 | 判定依据 | 备注 |
|:--|:--|:--|
| 学校练习 | 页眉有"第 N 课时 / 周末练习 / 单元练习"、班级姓名学号栏 | 权重高；决定"当前课堂进度" |
| 教辅 | 页眉品牌：学霸、补充习题、计算能手、口算题卡等 | 权重中；`source_name` 写品牌 + 页码或课次，如 `学霸 p3`、`计算能手 周三` |
| 试卷 | "测试 / 期中 / 期末"、总分栏 | 权重最高 |
| 课本页 | 课本版式、页码、"想想做做 / 练习 N / 试一试" | 不判题，`questions` 为空数组；有例题时给 `nodes` |
| 预习 | 家长明说是下周预习的课本页 | 同课本页，但强制记入本周预习清单 |
| 目录 | 标题"目录" | 不判题，`questions` 为空 |
| 参考答案 | 页眉"参考答案 / 答案"，密集算式无手写 | `questions` 为空，填 `answer_key` |
| 未知 | 其他 | 尽量避免 |

`source_name` 同一来源在不同页要写得一致（程序按 `material_type|source_name` 分组）。学校课时练写成 `学校课时练 第2课时`，周末练习写成 `周末练习 一`。

**预习自动判定**：课本页的单元编号比学校练习出现的最大单元更靠后时，程序会自动把这些知识点记入"下周预习"，不需要你标 `预习`。只有家长明确说"这份是下周预习"时才用 `预习` 类型。

## 2. 看图要求

- **整页都看**：每一道有作答的题都要输出，做对的也要（用于题量分母）。空白未作答的题也输出，`error_type` 写 `漏题`。
- **页眉隐私**：班级、姓名、学号不写进任何字段。
- **算式写成人话**：`96÷3+49`、`(70+23)÷3`、`14×3=42`。不要 LaTeX，不要 `$`、`\times`、`\div`、`\square`。填空用 □。
- **核对题目里的数字**：孩子常把题干的数字抄错（把"原价 80 元"抄成 30 元）。判题前先照着印刷题干核对一遍孩子算式里的每个数，抄错数字属于 `审题`。
- **竖式**：进位小字不是乘数的一部分。`709×5` 旁边的小 4 是进位，不是 `709×45`。

### 批改符号（teacher_mark）

这一项最容易看反，务必按下表判断：

| 痕迹 | 含义 | teacher_mark |
|:--|:--|:--|
| 一道长长的斜线扫过整段解答 | **这是对勾，表示做对了** | `right` |
| 小的 ✗、圈起来的 ✗、圈住某个数字或某句话 | 这一处错了 | `wrong` |
| 红笔在旁边写了正确答案或中间步骤 | 老师示范，通常伴随 ✗ | `wrong` |
| 完全没有红笔 | 没批改 | `none` |

只看这道题自己的痕迹，不要把整页的大勾算到每道题上。右下角的 `A 9.3`、`B 9.2`、`95` 是整页等级，填 `teacher_score`，整页一个，没有就留空。

### 订正规则

学校要求孩子拿到批改后立即订正，所以打叉的题旁边（或原处）常有重新写的正确答案。**订正最常见的形式是就地涂改覆盖**：原来的数字被新数字盖住写，只能看出笔迹重、有涂改痕迹，看不出原来写的是什么。

- `student_answer` 是孩子**最初**写的答案。看不清原值时就写"最初写错了（原来的数字已被涂改覆盖）"。
- 订正后的答案放 `corrected_answer`，并令 `has_correction: true`。
- `ai_verdict` 针对最初答案判定，所以有订正痕迹的题 `ai_verdict` 是 `wrong`。
- 打叉、当前答案正确、又完全没有涂改或补写痕迹的，才是真正的批改存疑：如实输出 `teacher_mark: wrong`、`ai_verdict: correct`、`has_correction: false`，并在 `analysis` 里写清"结果正确，老师打叉的可能原因是……"（常见原因：答句没写完、要求列综合算式、要求写出换算步骤、横线画错位置）。

### 独立验算

`ai_verdict` 必须是你自己算出来的结论，不能抄批改。**老师也会漏判**：打了勾的题也要算一遍，发现算错就照实写 `teacher_mark: right` + `ai_verdict: wrong`，页面上会标成「老师打勾但算错了」。应用题要核对列式是否符合题意，不只看结果。

### 其他

- **bbox**：整道题（题干 + 孩子全部过程 + 批改痕迹）在页面中的位置，`[x0, y0, x1, y1]`，0 到 1 的比例，左上为原点。宁可略大不要裁掉过程。两栏排版时不要跨栏。
- **confidence**：0 到 100，表示你对这道题判断的把握。字迹潦草、被手指遮挡、透字干扰、批改意图不明时降低。
- 看不清的地方可以先把该区域裁出来放大再看，不要猜。

## 3. 错因标签（error_type）

只对错题填写，必须从下表选一个主标签，可选一个副标签。

| 标签 | 含义 | 样例 | 补救方向 |
|:--|:--|:--|:--|
| 计算失误 | 方法对，算错 | `54+12` 写成 61；`269×9` 写成 2401 | 检查习惯，口算专项 |
| 审题 | 条件或问题看错、数字抄错 | "第 9 天"算成加 9 次；"最多/不够分"理解错；把 80 元抄成 30 元 | 圈关键词训练 |
| 概念不清 | 方法本身错 | 先加减后乘除；单位换算方向反；该加括号不加 | 讲解 + 变式练习 |
| 格式规范 | 结果对但答句没写完、漏单位、没按要求列综合算式或画横线 | 答句只写了半句被打叉 | 提醒清单 |
| 漏题 | 未作答 | 整题空白 | 检查习惯 |
| 策略缺失 | 大题没思路 | 找规律、鸡兔同笼类空白或只列了几个数 | 解题策略示范 |

判断顺序：先核对数字有没有抄错（审题），再看列式对不对（概念不清或审题），再看计算（计算失误），最后看格式。列式对、结果对、只有答句或书写问题的，才是格式规范。

## 4. 知识点编号（knowledge_point）

从 `知识点.md` 的二级标题取编号，如 `01.2`。规则：

- 混合运算题看有没有括号、含不含除法，分别对应 01.1 / 01.2 / 01.3；两步应用题归 01.4。
- **大纲里有单元、但 `知识点.md` 里还没有对应节点时**，按大纲的单元编号新建，如 `04.1`，并在 `new_node_title` 写节点名（`长度单位换算`）。不写名字的话页面上会显示成空标题。
- 课外班或竞赛类内容大纲里完全没有的，用 `EX.01`、`EX.02`……同样要写 `new_node_title`。同一份材料里同类题用同一个编号。
- 明显超出当前课堂进度的单元（如开学第一周出现千米换算）照常按内容归到该单元，程序会自动打"超前"标记。

## 5. 知识点内容（nodes）

课本页不判题，但要把讲解内容提炼到知识点：页面有**例题或方法总结**时给 `nodes`，纯练习页给空数组。习题页也可以给 `nodes`，用来补充新建的课外知识点。每个节点：

```json
{ "id": "02.2", "unit": "02", "title": "两三位数乘一位数的笔算（含进位）", "core": "用一位数依次去乘个位、十位、百位上的数。哪一位上乘得的数满几十就向左边一位进几，进位的数写小一点，乘下一位后要加上。例：14×3，个位 4×3=12 写 2 进 1，十位 1×3=3 加进位的 1 得 4，结果 42。", "example": "鸡的只数是鹅的 3 倍，鹅有 14 只，鸡有多少只？14×3=42（只）。", "guide": "让孩子一边算一边说：个位乘得多少写几进几，十位乘得多少再加进位的几。", "pitfalls": "忘加进位；进位小字被当成乘数；连续进位时漏加。" }
```

- `core` 是家长要讲的那句话，要具体到公式或步骤并带一个例子，不要写"掌握乘法"这种空话。
- `guide` 写家长怎么开口引导，`pitfalls` 写孩子容易踩的坑。这两段会直接印进辅导单的「下周预习」。
- 已有节点只会补空段落，不会覆盖家长手工维护过的段落（段首带 `<!-- manual -->` 的）。目录页不需要 `nodes`。

## 6. 参考答案页

```json
{ "material_type": "参考答案", "source_name": "学霸", "teacher_score": "", "questions": [], "nodes": [], "answer_key": { "source": "学霸", "text": "p2 1.(1)66 (2)42 ... 逐页逐题的紧凑文本" } }
```

`source` 与教辅页的 `source_name` 第一个词一致（如 `学霸`），后续该教辅的判题会以此为准。

## 7. pages.json 格式

数组，每页一个对象，顺序与 manifest 的 `pages` 一致：

```json
[
  {
    "material_type": "学校练习",
    "source_name": "学校课时练 第2课时",
    "teacher_score": "B 9.2",
    "questions": [
      {
        "n": "1",
        "bbox": [0.05, 0.12, 0.48, 0.30],
        "problem": "96÷3+49",
        "student_answer": "=32+49=81",
        "corrected_answer": "",
        "has_correction": false,
        "correct_answer": "81",
        "teacher_mark": "right",
        "ai_verdict": "correct",
        "knowledge_point": "01.2",
        "new_node_title": "",
        "error_type": "",
        "error_type_secondary": "",
        "confidence": 95,
        "analysis": "",
        "coach_prompt": ""
      }
    ],
    "nodes": [],
    "answer_key": null
  }
]
```

字段说明：

- `problem`：题干，简洁但完整；应用题保留数量条件。
- `analysis`：只对错题写，一两句说清卡点（不是复述错误）。
- `coach_prompt`：只对错题写，家长可以直接问孩子的一句话，引导而不是给答案。
- 做对的题 `error_type`、`analysis`、`coach_prompt` 留空。
- 做题日期、周、超前标记、来源权重由程序自动补，不用你写。

## 8. 练习出题规则（/weekly sheet）

给**每个重点问题**（`scope: "错题"`）和**每个预习知识点**（`scope: "预习"`）各出一组题：

- 计算类 5 题：2 题同构、2 题略变、1 题综合；应用题类 3 题：同构、略变、综合各 1。重点是应用题知识点（01.4、07.x）时出应用题，否则出计算题。预习组按该知识点的形式出，新学的笔算就出计算题。
- **家长给出天数时按天分卷**：每组加 `"day": N`。
  - 每天至少 3 个类型（3 组以上），本周重点问题都要覆盖到；同一重点可以在不同天重复出现，换数字、换情境。
  - 每天的练习卷**占满两页、不超过两页**：约 20 题，计算题与应用题搭配（应用题留作答空白，约占计算题两倍高度）。上面的每组题数是下限。
  - `practice` 命令发现某天超过两页会打印「超过两页：第 N 天 …」，此时删减那一天的题（优先删同构重复的）后重跑，直到不再提示。
- 数值：整数、万以内、不出现负数，除法必须整除，乘法不超过三位数乘一位数。
- 题干写成人看得懂的算式，不要 LaTeX。
- 错因是"审题"的，题干要含干扰条件或"最多 / 最少 / 一共 / 还剩"类关键词。
- 错因是"概念不清"的，前两题与错题完全同结构，只换数字。
- 预习组的第一题最简单，让孩子有信心。
- **`hint` 只印在答案页给家长看，练习卷上不出现**，所以可以直接写方法要点（如"个位 4×3=12，写 2 进 1"），不用担心透题。
- 每题给 `expression`：只含数字和 `+ - × ÷ ( )`，能直接算出 `answer`；程序会验算，算不通过的题会被丢弃。应用题的 `expression` 就是列式。

practice.json 格式：

```json
[
  {
    "topic": "除法与加减法的混合运算",
    "scope": "错题",
    "items": [
      { "kind": "calc", "level": "同构", "text": "84÷4+17", "expression": "84÷4+17", "answer": 38, "unit": "", "hint": "先算除法，再算加法。" },
      { "kind": "word", "level": "综合", "text": "每箱装 8 个，已装 9 箱，还剩 88 个没装，一共能装多少箱？", "expression": "88÷8+9", "answer": 20, "unit": "箱", "hint": "" }
    ]
  },
  {
    "topic": "两三位数乘一位数的笔算（含进位）",
    "scope": "预习",
    "items": [
      { "kind": "calc", "level": "同构", "text": "14×3", "expression": "14×3", "answer": 42, "unit": "", "hint": "个位 4×3=12，写 2 进 1。" }
    ]
  }
]
```

## 9. 孩子端题库模板（/weekly 归集第 5 步）

孩子端每天约 20 题，题目由模板批量生成：你写模板，程序按模板换数字、换故事，逐题验算。**每次同步的题库至少要够孩子每天都来、做两周（14 天）**，家长偶尔没及时更新，孩子也有新题做：程序按每组的 `daily` × 14 天（多留五成给周五闯关和加练）自动算每个模板生成多少道。`npm run kid bank` 和 `push` 会报「够做几天」，哪一组不够 14 天就给它多写一两个模板，或者放宽取值范围（数的范围太窄，生成不出那么多不重复的题）。不够 14 天的题库 `push` 会拒绝推送。

**家长只在周末整理错题时同步一次，两次同步之间不会再用 AI，这一份题库要覆盖最近 4 周纸面上错过的所有「知识点 × 错因」**（「已改善」的除外）。`bank` 和 `push` 会列出「最近 4 周纸面上错过、题库还没覆盖」的项，给它们补模板（往周的可以单独建一组「以前的题」，`bucket` 写 `往周未过关`）再 bank 一次，直到提示「都覆盖到了」。第一次同步（往周还没有题库）尤其要注意这一点。**题库只是练习，孩子端的结果不改纸面错误率。**

### 分组（`groups`）

你只写本周的新组，每天各抽 `daily` 题，合计 16 到 18 题；往周的题由程序自动带入（见本节最后），加起来约 20 题。

| 组 | bucket | 放什么 |
|:--|:--|:--|
| 口算热身 | 已掌握保温 | 本周题里用到的口算和先估后算，2 到 3 个模板，`daily` 6（可在 5 到 7 之间调，不写默认 6） |
| 2 到 3 组 | 本周重点 | `npm run sheet plan` 的重点问题，按「知识点 × 错因」各一组，`daily` 4 到 6（一天总题量仍约 20 题） |
| 关底题 | 本周重点 | `"boss": true`，`daily` 1，最难的一道，前面几组做完才解锁 |

**同一个「知识点 × 错因」要写 2 到 3 个不同 `level` 的模板**（同构 / 略变 / 综合，可以用不同题型）。孩子端会按他最近的首答正确率自动调三种难度的比例：最近 10 题 ≥85% 多出难的，最近 8 题 <60% 多出简单的。只有一种难度的话，这个调节就不起作用。

### 十三种题型

| format | 孩子怎么答 | 适合的错因 | 必填字段 |
|:--|:--|:--|:--|
| `oral` 口算 | 键盘填得数 | 计算失误 | `expression`；可选 `text`、`traps` |
| `estimate` 先估后算 | 先在三段范围里选一段，再填准确值 | 计算失误 | `expression`（范围由程序生成） |
| `first` 先算哪一步 | 点出先算的运算符 | 概念不清（运算顺序） | `tokens`、`first` |
| `steps` 递等式分步 | 每一行先点自己要先算的符号，再填得数，下一行照他的选择生成（`lines` 用来验算和写陷阱） | 概念不清、计算失误 | `expression`、`lines` |
| `fix` 小老师改错 | 点出小狗作业里最先出错的一行，再填正确得数 | 概念不清、计算失误（检查习惯） | `expression`、`shown`、`bad` |
| `clock` 拨钟面 | 把时针拨到位 | 概念不清（24 时记时法） | `hour`、`minute` |
| `multi` 多空题 | 一屏三四个空，都填完再交卷 | 漏题、格式规范、概念不清 | `blanks` |
| `word` 应用题 | 圈关键词 → 列式 → 递等式一行一行算 → 写答句（单位单独一格） | 审题、概念不清、格式规范 | `segs`、`choices`、`ask`、`unit`、`units`、`why` |
| `plan` 挑战题 | 先选「要先求什么」→ 列式 → 递等式 → 写答句 | 策略缺失（大题没思路） | `text`、`goals`、`choices`、`ask`、`unit`、`units` |
| `stat` 统计表 | 按正字或 ✓ 的记录填表，再答几个小问（选一类 / 列式 + 答句） | 计算失误、漏题、审题 | `cats`、`vals`、`asks`、`title` |
| `data` 整理数据 | 从一串数里点出符合条件的，再数个数写答句 | 审题 | `nums`、`ask`、`over`、`unit` |
| `column` 竖式 | 在格子里从个位填，进位、退位写在小格里 | 计算失误 | `expression` |
| `multistep` 分步应用题 | 每一步：求什么 → 列式 → 带单位的得数，上一步的得数变成下一步的数字卡 | 策略缺失、审题 | `text`、`steps`、`ask`，可选 `goals` |

所有题型都要写 `id`、`group`、`knowledge_point`、`error_type`、`level`、`hint`、`explain`。

**孩子端是整道题做完再判**（第五期）：每一步只收作答，不说对错，交卷后一次性给评价和正确做法；答错的题不给金币，过两天换个样子再来。所以：

- `hint` 是**本领 1 级「提醒」**用的一句话（孩子点了和这道题错因同名的本领徽章时显示），不能泄露答案。
- `explain` 在交卷后、和程序生成的「正确做法」（算式、递等式各行、答句）一起显示。
- 陷阱可以带一句 `say`：孩子答成这个数，评价里就说这句（比如「是不是从左往右算了？有减有乘，先算乘法。」）。`traps` 里的每一项、`choices` 里错的选项、`steps` 每行的 `traps` 都可以写 `say`。没写就用通用的评价。

**取值**（`slots`）：`[6, 9]` 两个整数是整数范围；其他数组是从里面挑一个（故事、人名）；`"={a}*24+12"` 是用前面的槽算出来的派生值（需要整除时，先取商再用派生值算被除数）。`where` 写必须成立的条件，如 `"{s}+{a}*({n}-1)<=21"`。数值遵守第 8 节的范围。文字里都可以用 `{槽}`。

### 应用题怎么写（孩子端最重要的题型）

**列式**：孩子不再只是三选一，而是用数字卡自己拼算式。数字卡由程序从正确算式里取（每个数一张，并标出它在题干哪一段，孩子圈过的会变成橙色）。列式有三档，跟着孩子最近的状态自动升降（规则同难度阶梯），新出现的「知识点 × 错因」从第 0 档开始：0 在 `choices` 三个算式里选一个；1 只给要用的数字卡自己拼；2 再多给一张用不上的干扰卡（取自标了 `"n": 1` 的噪音句里的数，没有就取错误选项里的数），只在略变以上的题出现。判分看算出来的值对、用到的数对，`100 − 12 × 3` 和 `100 − 3 × 12` 都算对；只拼出一部分（比如 `12 × 3`）会被告诉「这只算出了一部分」。

所以**正确算式里的每个数都要能在题干里找到**（「买两个送一个」这种隐含的 3、2 也会作为数字卡出现，没问题）；正确算式每一步都要能整除、不出现负数，否则 `npm run kid bank` 会报「正确算式算不下去」。

`flow` 可以去掉某些步骤（只能删，不能换顺序，必须保留 `say`）：如 `"flow": ["build", "chain", "say"]` 不圈关键词，`"flow": ["circle", "build", "say"]` 不写递等式。不写就是完整的 `circle → build → chain → say`（挑战题是 `goal → build → chain → say`）。

- `segs` 把题干切成几段，每段都能被孩子点。真正的关键词标 `"k": 1`（每题 2 到 3 个，要包括问题本身的关键处）；**每题加一句和计算无关的话标 `"n": 1`**，比如「店里还有一只猫」「今天是星期三」，训练孩子分辨哪些条件有用。
- `choices` 给 3 个算式，正确的标 `"ok": 1`；**错的选项要是孩子真实犯过的错**（从 `npm run sheet plan` 的代表错题里找），程序会把它的结果记成陷阱值，孩子答成这个数就自动归到这个错因。
- `ask` 是答句前半句（「答：第 {n} 次是」），`unit` 是正确单位，`units` 给 2 到 3 个容易混的单位（「时」和「小时」），`tail` 是单位后面的固定文字（如「30 分」）。孩子的问题主要是忘写单位，答句里单位单独一格。
- `why` 在孩子圈完关键词后显示，说清哪几个词关键、哪句用不上。

**凡是文字应用题都先圈关键词**：`word`、`plan`、`multistep`、`data` 第一步都是圈关键词。`word` 用 `segs` 标关键词和噪音；`plan`、`multistep`、`data` 也可以写 `segs`（写法同应用题，`text` 仍要写），不写的话程序按逗号、句号、问号切开，带数（包括「两个」「一倍」这样的汉字数）的句子和问句算关键词。想练分辨噪音的，就自己写 `segs` 并加一句 `"n": 1`。

挑战题（`plan`）的写法：`text` 是完整题干（不切段），`goals` 给 3 个「要先求什么」的选项，正确的标 `"ok": 1`，其余字段和应用题一样。放在关底题组里，一周 1 到 2 个模板就够。

第三单元「数据的收集与整理」用两种题型（课本只有统计表，没有条形图）：

- `stat` 统计表：题干给正字（`"record": "tally"`）或 ✓（`"record": "check"`）的记录，孩子先填表（各类和合计），再答 2 到 3 个小问。各类的数在 `vals` 范围里随机、不并列。`asks` 每一项是一个小问：`max` / `min`（选哪一类最多 / 最少），`max-min`（最多的比最少的多多少），`a-b`（随机挑两类，大的减小的），`a+b`（两类一共）。`t` 是小问的问题，`pre` 是答句前半句，里面可以用 `{a}` `{b}` 表示挑到的两类。表填错了，后面的小问照孩子自己填的数往下走；**按小问给金币**，答错的那一问不给。
- `data` 整理数据：从一串数里点出符合条件的，再数个数。`nums` 写成 `"12×(10..38)"`（12 个数，每个在 10 到 38 之间），`ask` 是 `over`（超过）、`under`（少于）或 `atleast`（不少于），`over` 是界限（可以给几个，每题挑一个）。程序会故意放一个正好等于界限的数，专门检查「超过 20」有没有把 20 也算上。

竖式和分步应用题：

- `column` 竖式：模板只写 `expression`（`{a}×{b}` 乘一位数、`{a}+{b}`、`{a}-{b}`），格子由程序排。孩子从个位填起，进位、退位写在上面的小格里。判分能认出「忘了加进位」「忘了退位」。
- 除法竖式（06 单元）：`column` 的 `expression` 写 `{a}÷{b}`（除数一位数），商写在上面，下面一行乘积、一行减下来再落下一位。`"need": "zero"` 只出商中间有 0 的，`"endzero"` 商末尾有 0，`"rem"` 有余数。能认出商中间漏写 0、余数比除数大。想让被除数正好整除，用派生槽：`"slots": { "q": [101, 309], "b": [2, 3], "a": "={q}*{b}" }`。
- 验算：`column` 加 `"check": true`，做完竖式再验算一次（除法：商 × 除数 + 余数；加减：逆运算；乘法：估一估）。验算对了才有过程奖，不影响这题对不对。
- `multistep` 分步应用题（两步计算的实际问题，01.4、07 单元）：`steps` 每一项是一步：`ask`（这一步求什么）、`e`（这一步的算式，后一步要用上前一步的得数，写成 `{s1}`、`{s2}`）、`pre`（这一步得数前面的话）、`unit`、`units`。可以写 `goals`，先选「第一步求什么」。`ask` 是最后的答句前半句。每一步孩子自己拼算式、写带单位的得数，上一步写的得数会变成下一步的蓝色数字卡；第一步算错了，第二步照他写的数判方法对不对。

{ "id": "t51", "group": "g6", "format": "column", "knowledge_point": "02.3", "error_type": "计算失误", "level": "略变",
  "slots": { "a": [112, 399], "b": [3, 9] }, "expression": "{a}×{b}", "hint": "个位乘完，进位记在十位上面。", "explain": "从个位乘起，每一位都要加上进位。" }

  "slots": { "a": [32, 49], "n": [2, 4] }, "text": "图书馆上午借出 {a} 本书，下午借出的是上午的 {n} 倍。这一天一共借出多少本书？",
  "goals": [{ "t": "下午借出多少本", "ok": 1 }, { "t": "一共借出多少本" }, { "t": "上午比下午少借多少本" }],
  "steps": [{ "ask": "下午借出多少本", "e": "{a}*{n}", "pre": "下午借出", "unit": "本", "units": ["本", "倍"] },

答句几格、有余数（04 毫米分米千米、06 两三位数除以一位数）：

- 多空题一行可以有几个 □，`e` 写成数组按顺序对应：`{ "t": "{p} 米 = □ 千米 □ 米", "e": ["{j}", "{n}"] }`。
- 口算有余数：`"remainder": true`，`expression` 写 `{a}÷{b}`，孩子填「商 □ …… □」。余数比除数大会被指出来。
- 应用题答句有几格：写 `answers`（每格的得数 `e` 和单位 `unit`），`ask` 里用 □ 标出每一格的位置，如 `"ask": "答：可以放 □，还剩 □。"`，`units` 里要有每一格的单位。正确算式是有余数的除法（如 `{a}÷{n}`）时，自动不写递等式，列式只看算式对不对。

转转盘、摸球、量身高、调查兴趣小组这些要动手的，和「你能提出哪些问题」这类开放题，不放到屏幕上。

几个容易写错的地方：

- `steps` 的 `lines`：`pre` 是这一行已经印好的部分（直接写 − × ÷），`e` 是孩子要填的那个数怎么算；最后一行的 `e` 必须等于整道题的得数。
- `fix` 的 `shown` 是一份**算错了**的递等式，按孩子真实的错法写（比如从左往右算），用派生槽算出错的中间数；`bad` 是最先出错的那一行的下标（从 0 开始）。孩子要填的是整道题正确的得数。
- `clock` 的 `minute` 只能是 0 或 30；几时半最容易错成指在整点上，程序会自动把它记成陷阱。
- `multi` 的每个 `t` 里用一个 `□` 表示要填的位置，3 到 4 个空。
- 金币按「题型 × 难度 × 分组」自动标价，不用你算。`npm run kid bank` 会报每个模板生成了几道和跳过的原因，少于 10 道就放宽取值范围或换写法。

### 调节项（`tuning`）

写在模板 json 里，或者之后用 `npm run kid tune <周> 键=值 …` 改（改完要再 `npm run kid push`）。家长说「这周题少一点」「先别提醒单位了」之类的话时改这里。

| 键 | 默认 | 含义 |
|:--|:--|:--|
| `unit_hint` | 1 | 1：答句里留虚线空格提醒单位；0：不提醒。孩子最近两周忘写单位少于一成后改成 0 |
| `blank_hint` | 1 | 1：多空题有空没填时不让交卷并提醒；0：不提醒，交了算一次漏题 |
| `slow` | 1 | 「慢慢来」的严格度：0 关掉，1 标准，1.5 更严（最短思考时间变长） |
| `boss_day` | 5 | 星期几是闯关日（1 到 7，0 关掉）。那天各组题量减半，另加 8 道最难的题 |
| `bedtime` | 20:30 | 这个时间以后小狗睡觉，不能开始做题 |
| `focus_boost` | 1.5 | 「本周重点」的金币倍率，可调 1.2 到 2 |
| `wish`、`wish_days` | 无、4 | 心愿单：家长许的现实奖励（如「周末去科技馆」）和这周要做完任务几天才能兑换。不写 `wish` 就不显示 |
| `note` | 无 | 家长留言（如「周六去公园」），孩子每天第一次打开时小狗在早安里转达。改完要 push |
| `read_aloud` | 0 | 1：题干旁边出现喇叭，用浏览器朗读题目。家长觉得孩子读题吃力时再开，审题训练期间别开 |
| `kid_name`、`pet_name` | 无 | 改孩子或小狗的名字（各最多 6 个字），push 时写进孩子端存档 |
| `extra` | 10 | 做完今天的任务后最多还能加练几题（金币减半），0 关掉 |
| `minutes` | 25 | 一天做题超过这么多分钟后不再给加练 |
| `daily.<组 id>` | — | 某一组每天抽几题，如 `daily.g2=8`（只能用 tune 命令改） |

### 往周的题：程序自动带入，不用你写

运行 `npm run kid bank` 时，程序会看前几周的「题库」和「答题」：

- **上周**屏幕第一次就对不到 85%（或根本没练到）的模板，进「以前的题」组（往周未过关，金币 ×1.2）；
- 过关的模板，在之后**第 1、2、4 周**各回来一次，进「老朋友」组（保温，金币 ×0.8）；
- 本周新模板已经覆盖的「知识点 × 错因」不带。

所以要先 `npm run kid pull <上周>` 把答题记录取回来，再写本周模板。随机数按「周 + 模板 id」取，带过来的模板会自动换一批数字。命令的输出会列出带了哪些，汇报时告诉家长。`pull` 的输出里标了「刚降了一档，需要家长讲一讲」的知识点，也要转告家长。
