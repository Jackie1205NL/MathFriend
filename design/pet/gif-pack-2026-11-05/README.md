## 清单与目录

`manifest.json` 由动作盘点维护；`items` 每项包含 `id`、`stage`（2 或 3）、中文 `name`、`category`、相对本目录的 `raw`、八个毫秒数 `durations`、`coverage` 数组和 `note`。阶段说明放在 `stages` 中。原始连续帧图放在 `raw/`，提示词及生成来源保留在本目录，不能用白底图冒充透明图。

每张原图按 **4 列 × 2 行**、从左到右再从上到下读取八帧。`scripts/build-gif-shared.mjs` 原样复用上一轮已经验证的编码器，作为本包内唯一的编码实现，不依赖前轮预览目录。所有帧共用一个裁剪框与缩放，保留跳跃高度和固定物体位置；输出为 **512 × 512、八帧、透明、循环 GIF**。

## 工作流

在本目录运行：

```bash
node pack.mjs check             # 校验清单；缺失原图显示待生成
node pack.mjs build             # 合成已有原图，跳过没有变化且已通过的输出
node pack.mjs build s2-disc      # 只处理指定动作；可传多个 ID
node pack.mjs validate          # 不重新编码，独立复核所有现有输出
node pack.mjs preview           # 刷新 catalog.json 与可直接打开的 preview.html
node pack.mjs zip               # 全部动作 passed 且视觉确认后才打包
```

原图必须有真实 Alpha，各格需要非空主体与透明区域；不接受只有 Alpha 通道但像素全部不透明的图，不自动抠白、不修白毛。编码后检查帧数、尺寸、循环、每帧延迟、独立帧、透明区域，以及相对 PNG 帧的 Alpha/清屏一致性。失败项不会作为通过素材进入预览或打包。`catalog.json` 记录技术检查和文件哈希，不反写动作清单。

技术校验通过后，还要人工看角色身份、手脚数量、飞盘与澡盆等道具、起跳落地、首尾接续和深浅底边缘。预览默认静帧、懒加载；可以按阶段和分类筛选，逐张播放/暂停、切换棋盘底，并显示总数与通过/待生成/不通过数量。技术检查不能代替视觉确认。

每次更新会生成 `s2-contact.png` / `s3-contact.png`，按清单顺序并排展示每个动作的首帧和中帧；后续增量制作时可以为未生成的动作留出标记。`catalog.json` 同时记录主体边界、透明外边距和整体包围框底部的位移范围；非跳跃动作的明显漂移会提示目检，接飞盘和小跳保留真实腾空高度，不自动把所有帧底对齐。

打包命令要求清单内每项都通过；有待生成或不通过项时会拒绝打包。两包都包含人可读的 `coverage.md`、入口映射 `coverage.json` 和阶段总览图，来源包另含最初的阶段布局参考及本包共享编码器，解压后可以独立重建。

Git 中保留 GIF、`00.png` 静帧、raw 完整连续帧图、提示词、清单、预览和重建脚本。ZIP、派生 `01.png`～`07.png` 与 `timing.ffconcat` 由本目录的 `.gitignore` 排除。拉取后现成的 `preview.html` 可直接打开；如需重新校验或重建，先运行 `node pack.mjs build` 恢复派生帧，再运行 `node pack.mjs validate`。刚检出的副本缺少被忽略的派生帧是预期情况，不代表 GIF 损坏。

合成环境需要 Node.js 20 或以上、`sharp`、FFmpeg，以及 `zip` / `unzip`。当前仓库已提供 `sharp`；独立解压来源包后可安装 `sharp` 再运行相同命令。
