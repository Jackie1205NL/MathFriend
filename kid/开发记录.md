# 孩子端开发记录

给接手开发的人（或另一个 Claude）看。每做完一段工作，把「进度」和「过程记录」更新一下。

最后更新：2026-10-03（第五期 5A）

## 1. 要做的是什么

家长每周把作业和试卷扫描进来，家长端归集错题、出纸质辅导单（这部分早就有了）。孩子端是新加的：一只柴犬，靠做题赚金币来喂养、陪玩、学本领。题目不是固定题库，而是**每周按家长端的错题重新生成**，孩子在屏幕上的答题结果再回到家长端，决定下周的题怎么调。

```
家长端（本地）                               孩子端（Netlify）
扫描件 → /weekly → 错题/周.md
        /weekly sheet → 辅导单 PDF（周末用）
        + Claude 写题库模板 ──npm run kid push──→ 题库包（含答案，存 Blobs）
                                              孩子每天约 20 题 → 金币 / 技能点 → 照顾小狗
        答题汇总写回周 md ←──npm run kid pull── 答题流水
```

孩子的真实问题（来自错题数据）：**审题**（题没读完就动手）、**格式规范**（尤其是忘写单位）、口算粗心。不是不会，是抢快。所以整套规则不奖励速度。

可视化的设计稿和早期原型在 `design/孩子端设计稿.html`、`design/孩子端原型.html`，浏览器直接打开。其中「分支与数据契约」一节已过时，以本文件为准。

## 2. 已定的设计决定（和原因）

| 决定 | 原因 |
|:--|:--|
| 一个分支、两个目录（`kid/` + `shared/`），不用两个长期分支 | 最常见的改动（加题型、加字段）两边都要改，两个分支每次要提交两遍还容易漏 |
| 孩子端只引用 `shared/`，靠构建隔离数据 | 孩子端站点里不能有错题和截图；仓库是公开的 |
| 判分、金币、存档全在后端 | 答案不发给页面；金币不能在浏览器里改 |
| Claude 只写**模板**，程序实例化并验算 | 不用 API key；每周要 200 多道变式，手写不现实 |
| 屏幕成绩不并入纸面错误率 | 屏幕题简单且量大，会稀释作业错误率、误判「已改善」。纸面不再犯才算过关 |
| 金币 = 题型基础分 × 难度 × 来源 × 作答质量 + 过程奖 | 题越长每分钟赚得略多，刷口算不划算；过程奖奖的是圈关键词、写全步骤 |
| 没有倒计时、排行榜、抽卡、扣金币、宠物生病 | 孩子的问题是抢快；不用损失和内疚驱动 |
| 应用题：题干每段都能圈，故意放噪音，圈完再对答案 | 训练分辨哪些条件有用；先自己判断再看反馈 |
| 「算和答」一步保留选好的算式 | 不然等于又列一遍式 |
| 单位是答句里单独一格，键盘上有单位键，不给选项提示 | 孩子的问题是**忘写**单位，不是写错；提示分两档（留空格 / 不留） |
| 照顾要花金币，免费的只有每天 3 次摸摸 | 之前免费野果和摸头就能满足需求，金币没意义 |
| ~~三项需求都 ≥60 时成长值 ×1.2~~（第四期改成早安小礼物） | 照顾有回报，但不惩罚 |
| 小狗按「陪伴天数 + 最早日期」长大，不按金币（第四期） | 每周来 4 到 7 天长大日期一样，学期节奏可控；金币只当钱用，不奖励刷题 |
| 学期是一份配置 `SEASON`，换学期时旧宠物住进老朋友墙 | 下学期只换配置和素材，不清存档 |
| 地点插画、明信片、领结、帽子、学士帽先用代码画 | 素材还没画；家长画好后换成图片 |
| 宠物是柴犬，五个阶段靠耳朵、配饰、项圈星星数区分 | 用户和孩子选的；之前的占位形象阶段差别太小 |
| 需求按时间戳在读取时计算 | 不需要定时任务 |
| 存储用 Netlify Blobs（键值） | 数据量小，不需要数据库；用户决定用 Netlify 只部署孩子端 |

### 后端存了什么（Blobs 的键）

| 键 | 内容 |
|:--|:--|
| `pack` | 当前题库包（含答案），家长端 `PUT /api/kid/pack` 写入 |
| `state` | 小狗和孩子的全部状态：名字、孩子的名字、金币、需求、背包、技能点、本领、难度阶梯、故事进度、本周出勤、日记（`album`），第四期加了陪伴天数 `days`、学期 `season`、储蓄罐 `jar`、明信片 `cards`、散步 `trip`、早安礼物 `gift`、藏骨头 `hide`、老朋友 `alumni`、毕业 `grad`、每月首答 `months` |
| `dev-clock` | 只在本地开发和 dev 分支部署：拨过的时钟（`POST /api/kid/dev/clock {date, time}`，dev 站要带同步令牌） |

正式站（uat 的生产部署）存在 Blobs 存储 `kid`；dev 分支部署和预览存在 `kid-dev`（`kid/functions/kid.mjs` 按部署类型选），在 dev 上试玩不会动孩子的正式存档。两边的题库也是分开的，dev 站要单独推。
| `day:<日期>` | 当天抽到的题和每题进度（错了几次、做到第几步、结算结果） |
| `log:<周>` | 该周每次作答一行，家长端 `GET /api/kid/log?week=` 取回 |
| `fail:<用户名>` | 登录失败计数（连错 5 次锁 5 分钟，按用户名分开） |
| `users` | 账号表：`[{ id, name, salt, hash, off, created, seen }]`，密码只存加盐哈希 |

**账号**：每个孩子账号有自己的小狗和存档，题库大家共用。第一个孩子账号 id 是 `main`，用不带前缀的老键（`state`、`day:*`、`log:*`，以前的存档就是它的）；其他账号的键前面加 `u:<id>:`。`pack`、`users`、`fail:*`、`dev-clock` 是共用的。第一次用时，程序用环境变量 `KID_PIN`（和 `KID_USER`，默认「宝贝」）建第一个孩子账号；以前用口令登录的 cookie，在管理员没改过这个账号的密码前继续有效。家长端 `pull` 默认取第一个孩子账号的记录，`KID_USER=用户名` 取别的。

### 接口

- `POST /api/kid/login {name, pin}`：用户名 + 4 位密码（管理员用户名 `admin`，密码是环境变量 `ADMIN_PIN`），对了发 cookie；`POST /api/kid/logout` 换人。
- `GET/POST /api/kid/admin/users`、`POST /api/kid/admin/users/<id> {pin | name | off}`：管理员建账号、重置密码、改名、停用。
- `GET /api/kid/state`：小狗状态 + 今天的题（已去掉答案）。
- `POST /api/kid/answer {item, steps: [每块积木的作答], ms}`：整道题交卷判分（被守护接住时返回 `caught`，改好再交一次）。
- `POST /api/kid/act {kind, …}`：起名（`name`、`kidname`）、早安（`greet`）、买东西、喂食、洗澡、陪玩、摸摸、学本领、加练、小事件（`event`）、散步（`trip`）、储蓄罐（`jar`）、藏骨头（`hide`、`cup`）、毕业典礼（`ceremony`）。把戏只在页面里演，不走后端。
- `PUT /api/kid/pack`、`GET /api/kid/log`：家长端同步用，请求头带 `x-sync-token`。
- `POST /api/kid/admin/pack {pack}`：管理员在账号管理页上传题库包（命令行推不上去时用，比如站点开了 Netlify 登录保护）；`GET /api/kid/admin/users` 顺带返回现在题库的周、题数、够几天。

## 4. 规则速查

数值都在 `shared/contract.js`，改一处两端生效。

- **题型基础分**：口算 1、先算哪一步 2、拨钟面 4、先估后算 4、递等式分步 6、小老师改错 6、多空题 6、应用题三步 12、挑战题 25。
- **难度**：同构 ×1、略变 ×1.3、综合 ×1.6。**来源**：本周重点 ×1.5、往周未过关 ×1.2、下周预习 ×1、已掌握保温 ×0.8。
- **整题判分**（第五期）：题目由积木拼成（`FLOWS`，模板可写 `flow`），每一步只收作答，交卷时 `judge()` 逐步判分，每一步照孩子自己的结果往下走。答对给全价，答错 0（不扣），没有订正。被 3 级守护接住改对的，金币照给、连击不断，但不算首答正确。
- **过程奖**：应用题关键词圈得刚好 +2、圈全但多圈 +1；递等式每行都对、先估后算估对、多空题没漏空、挑战题选对「先求什么」+2。用了 2 级帮忙的题没有过程奖。连续 5 题第一次就对 +5。加练的题金币减半。
- **急着答错**：整道题的用时低于题型的最短思考时间又答错。连击清零，接下来 3 题先盖住几秒（「慢慢来」）。只是忘写单位不算。
- **技能点**（第五期）：做出习惯就攒——圈得刚好→灵鼻子，单位写对→收尾巴，估对或递等式每行算对→稳稳爪，先算的顺序对→排排队，先求什么对→探路。攒满 `SKILL_EVERY` 次得 1 点，每个本领每天最多 1 点。一整天没有急着答错，得 1 点「巡逻」。本领每级要 3 / 6 / 10 点。
- **本领在答题时**：陪伴条上亮出这一步用得上的徽章（`SKILL_AT`），孩子点了才用：1 级提醒每天 3 次，2 级帮忙每天 1 次（`SKILL_L2` 是能用的积木），3 级守护每周 1 次，没用上退回。次数存在 `state.uses`。
- **列式档位**：`state.tiers["知识点|错因"]`，0 选算式、1 拼算式、2 加干扰卡，升降规则同难度阶梯，新的从 0 开始。
- **需求**：饱食、心情、清洁每天各降 25 / 22 / 15，最低 20。照顾一天约 55 金币。前一天睡前三项都 ≥60，第二天第一次打开有早安小礼物（骨头饼干或 10 金币）。
- **成长**（第四期）：做完当天任务算陪伴 1 天（周末也算，毕业典礼后不再计）。少年 10 天且 10/24 以后，青年 26 天且 11/21 以后，成年 42 天且 12/26 以后；1/20 毕业周，1/22 毕业典礼。`grow` 只是「一共赚过多少金币」。
- **花钱**（第四期）：地点摆设 9 件（开放后才能买）、月度限定 4 件、散步（院子免费、公园 20、雪山 30，每天一次，心情 +20）、储蓄罐 1,500（每次存 100，毕业典礼兑现，10 枚可兑换 1 个签名只做显示）。
- **明信片**：按学期种子排好「明信片日」（从第 3 天起每隔 1 到 2 天），那天或之后的下一次散步带回，最多欠一张。每个地方 4 张。故事这一章读完了，周五闯关通关改送明信片。
- **难度阶梯**（第二期）：每个「知识点 × 错因」有一个档位。最近 10 题第一次就对 ≥85% 且跨两天，升一档；最近 8 题 <60% 或连错 3 题，降一档。档位决定抽题时三种难度的比例。

### 第三轮：关键词的粒度和扣分（2026-10-04）

- 按句切又太粗（句句都是关键词，圈了等于没圈），按词切太细。用户给的标准是**按意思切成短语**：「图书馆 | 上午借出★ | 44 本书★ | 下午★ | 借出的是 | 上午的 3 倍★ | 这 | 一天一共★ | 借出 | 多少本书？★」。这种切法程序猜不准，所以**由出题时在模板里写 `segs`**（rules.md 改了规则和四种题型的示例）；模板写了 `segs` 原样用，没写的才由程序兜底（`midSegs`：按标点切，再在数和提示词前断开，问句只分两段）。
- 评分放宽：关键短语每 4 处可以漏 1 处、没圈噪音句，就算圈得好（过程奖照拿），点评仍指出「也可以圈上」哪几处；漏圈从来不影响这道题对不对。
- 「试一试」的示范题也改成按短语切。
- 第四轮：用户漏圈了「第 3 次」却被夸「圈得很好」。关键短语改成两级：`"k": 2` 必圈（列式要用的数、决定怎么算的词、问的是什么），`"k": 1` 帮助理解（「上午借出」「下午」）。必圈的一处都不能漏，宽容只给 `k: 1`；漏了必圈的用红色虚线标出，小狗说「是解这道题最要紧的，一定要圈上」，下面的对话也跟着说。rules.md 的规则和四个示例都标了两级。
- 验证：专项 18 项（含「5 处漏 1 处算圈得好」）、浏览器模拟 56 项（126 题）、后端回归 63 项，全部通过。

### 部分得分（2026-10-04）

用户反馈：4 个空错 1 个就整题没金币，打击信心。改成**按做对的部分给金币**，题目仍然算错（不算第一次就对、过两天换个样子再来、没有过程奖）：

- 一般按做对的步骤 / 空格占比（圈关键词不算，它只管过程奖）；统计表仍按小问；竖式按写对的位数，除法竖式按商的每一位和余数。
- **方法错了不给**：应用题、挑战题的列式或「先求什么」错了就是 0，部分得分只给方法对、细节出错（算错一个数、忘写单位、错一个空、错一位）。只有一步的题（口算、拨钟面、先算哪一步）本来就是全对或全错。
- 实测（只错一处）：多空题 67%～75%，应用题忘写单位或得数算错 80%，挑战题 83%，统计表 67%，竖式错一位 75%，整理数据、先估后算、改错 50%。
- 交卷页：「差一点点！做对的部分有金币 ＋N」，小狗说「大部分都做对了，就差一点！」。

## 7. 怎么运行和验证

```bash
npm run kid:dev                                   # http://localhost:5175，孩子账号「宝贝」密码 1234，管理员 admin 密码 9999
curl -X POST -H 'content-type: application/json' -d '{"date":"2026-11-21","time":"16:00"}' http://localhost:5175/api/kid/dev/clock   # 本地拨时钟，看学期里任何一天
npm run kid pack 2026-W40 /tmp/pack.json          # 从周 md 的「题库」生成题库包（含答案，别提交）
curl -X PUT -H 'x-sync-token: dev' -H 'content-type: application/json' \
     --data @/tmp/pack.json http://localhost:5175/api/kid/pack    # 推到本地孩子端
```

本地存档在系统临时目录的 `shuban-kid-dev/` 下，删掉就是全新的小狗。想在不是周五的日子测周五闯关，把题库 `tuning.boss_day` 设成当天是星期几（1 到 7）。

改完至少跑：`npx eslint shared kid server/kid.js`、`npx tsc --noEmit -p .`、`npm run kid:build`，再在浏览器里把改到的题型点一遍。

### 在 dev 站试玩（https://dev--mathfriend.netlify.app）

dev 站开着 Netlify 登录保护时命令行推不上去，改用文件上传：`npm run kid demo 2026-W41 /tmp/demo.json`（或 `npm run kid pack <周> /tmp/pack.json`），用 `admin` 登录 dev 站，在账号管理页的「题库」卡片上传。文件含答案，用完删掉，别放进项目文件夹。

```bash
KID_URL=https://dev--mathfriend.netlify.app npm run kid demo              # 推一份体验题库（rules.md 的示例模板，13 种题型都有）
KID_URL=https://dev--mathfriend.netlify.app npm run kid push 2026-W41     # 或者推某一周真实的题库
KID_URL=https://dev--mathfriend.netlify.app npm run kid clock 2027-01-22  # 拨 dev 站的日期，不写日期拨回今天
```

`KID_URL`（和 `KID_TOKEN`）只对这一条命令生效，不改 `npm run kid link` 保存的正式地址。同步令牌用 Netlify 上的 `SYNC_TOKEN`（dev 和正式站默认同一个）。
